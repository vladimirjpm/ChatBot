What to say at the interview

  • "I implemented a RAG pipeline: PDF → text extraction → chunking → embeddings → Qdrant → semantic search. This lets the bot answer strictly from documents, falling back to general model knowledge when none are present."
  • "For SSE I didn't use EventSource because I need POST. I wrote a ReadableStream reader with TextDecoder manually — that gave full control over buffering and AbortController."
  • "Two grounding modes — soft for interview and strict for document assistant. Different prompt logic and UX flow over the same RAG pipeline."
  • "Prompts live in locales/en.json and locales/ru.json — single source of truth for both frontend and backend. An automatic parity test prevents adding a key to one file and forgetting the other."
  • "Docker multi-stage build with proper layer caching: csproj files are copied as a separate layer before source, so changing code without changing dependencies doesn't re-run restore."
  • "WebApplicationFactory with interface substitution — tests are deterministic, don't need a real OpenAI key and don't touch the network."
  • "Used IEmbeddingGenerator from Microsoft.Extensions.AI instead of SK experimental API — this is a provider-agnostic interface that lets me swap OpenAI for Ollama without changing any code."
  • "Qdrant Cloud requires payload indexes for filtered scroll — I discovered this in production, diagnosed via structured logs, and fixed by creating keyword indexes on scope/sessionId/documentName in EnsureCollectionAsync."
